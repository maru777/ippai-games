# 設計メモ

## 方針（確定）
- Web（HTML5 Canvas）、素の JS、依存なし。スマホのタッチ優先、PC はキーボード対応。
- 論理解像度 240×320。4 色パレットのドット風。
- 年代は 2000 年代半ば（i アプリ・Flash 全盛期）基準。

## ループパズル（予備に移動）
- 名称はニコリの商標を避け「ループパズル」。ルールのみ採用。
- 問題は事前生成の固定問題（5×5 を 30 問程度）。生成スクリプトで解の一意性を検証して `data/` に置く。

## 補足
- 入力は `Input.pointers` でマルチタッチに対応（マリさんの冒険の左右＋ジャンプ同時押し用）。
- マリさんの冒険のステージは `STAGES`（ビルダー関数）で定義。ゲームを足す場合も同様にデータで増やせる。
- マリさんの冒険の名称・キャラ・素材はオリジナル（任天堂作品の素材は不使用）。

## オンライン対戦（かべレース）
- 中継は Cloudflare Workers + Durable Objects の汎用中継（`works/online/server/`）。ルームコードは 4 桁の数字、接続元 Origin を制限。
- 判定は各ブラウザが同じルール（`wall-race-rules.js`）で行い、手だけを送り合う。接続先は `src/core/config.js` の `RELAY_URL`（または URL の `?relay=`）。
- 4 桁は推測されやすい（約 1 万通り）。無料枠の消費対策は Origin 制限に依存する。

## かべレースの先手・後手とチャット
- 先手・後手はランダム（CPU 戦は開始時、オンラインは部屋を作った側が抽選して `start` で通知）。
- チャットはオンライン対戦のみ。定型スタンプ（絵文字 8 種。番号で送信）と自由入力（30 文字まで）。送信は 1 秒に 1 回まで、自由入力は相手側で「文字:非表示」にできる。サーバーは中身を解釈しない（再デプロイ不要）。
- 画面上部にログ（3 行・上下ドラッグかホイールでスクロール、約 50 件保持）と、直近のスタンプ枠（3 秒）を置き、盤面には重ねない（盤面の上端は y=62）。
- 自由入力は HTML の `input` を画面下に重ねる。`core/input.js` は `input` 要素への打鍵をゲーム操作として扱わない。

## かべレースの見た目（ネオン調）
- かべレースだけ 4 色パレットから外れ、ネオン調（濃紺の背景、自分=シアン、相手=マゼンタ、壁は置いた側の色で発光）。描画ヘルパーは `wall-race-theme.js`。
- 高解像度（canvas を 2 倍で描画。論理座標は 240×320 のまま）。シェルは `game.hiRes` / `noHud` / `skipReady` / `silentOver` / `drawOver` / `tick` の任意フックでこれに対応する。
- 演出: コマの滑らかな移動と残像、壁が落ちる動きと波紋、手番の縁の脈動、勝敗の演出、効果音。

## かべレースの投了
- プレイ中はいつでも右下の「投了」から降参できる（確認ダイアログあり。相手の番でも可）。CPU 戦では負け、オンラインでは相手に `{ k: 'resign' }` を送り、相手は勝ちになる。サーバーは中身を解釈しないため再デプロイ不要。

## ボードゲーム（対戦）3 本とメニューのタブ
- メニューは「アクション」「ボード（対戦）」の 2 タブ（`registry.js` の `tab`）。かべレースはボード側。
- 追加: リバーシ（8×8）/ 四目並べ（落とし込み 7×6）/ ドット囲み（5×5 の点・箱 16）。名称は商標を避けて一般名。
- 共通の画面は `duel-shell.js`（メニュー: CPU 戦・1 台で 2 人（交代）・部屋をつくる/入る、CPU の強さ 3 段階、投了、結果、オンライン）。新しいゲームは spec（ルールの `apply` ・CPU の `ai`・盤の描画と操作）を渡すだけ。ネオン調の描画は `wall-race-theme.js` を共用（かべレース本体は変更していない）。
- ルールと CPU は描画から独立（`reversi-rules.js` / `four-rules.js` / `dots-rules.js`）。テストは `node works/collection/tests/rules.test.mjs`。
- オンラインの通信は既存の中継をそのまま使う。送るもの: 開始 `{k:'start', first}` / 手 `{k:'act', a}` / 投了 `{k:'resign'}`。判定は各ブラウザが同じルールで行う（手だけ送り合う）。チャットは未対応。
- 操作: リバーシは光る升をタップ。四目並べ・ドット囲みは「選ぶ → もう一度タップか確定ボタンで決定」（誤タップ防止）。
- CPU: リバーシ=評価（場所の価値＋置ける数）の αβ（かんたん=貪欲＋ゆらぎ、ふつう=3 手、つよい=5 手＋終盤の読み切り）。四目並べ=αβ（2 / 4 / 7 手）。ドット囲み=箱を取る・3 辺目を避ける、つよい=残り 16 辺以下で読み切り。
- 先手・後手はランダム。CPU 戦のベストは難易度別の勝ち数（`<id>-<level>`）。

## ツリー砦（スキルツリー式のタワーディフェンス）
- 参考: OUTHOLD（ツリー形式の強化が中心の短い TD。公開情報の範囲。ツリーの具体は独自設計。名称・素材はオリジナル）。メニューは「アクション」タブ。
- 流れ: ツリー画面（ドラッグで動かす・タップで選ぶ・「かいほう」「もどす」）→「出撃」→ 戦闘（砦が自動攻撃、画面タップで追加の一撃、「撤退」可）→ 結果 → ツリーへ。稼いだポイントが貯まり、ノードの返金は無料。
- ツリー（20 ノード）: 上=攻撃（攻撃力・貫通・会心・**爆弾砲**）/ 右=速さ（連射・ダブルショット・射程・**雷撃**）/ 左=守り（耐久・修復・防壁・**回転刃**）/ 下=経済（ポイント・波ボーナス・凍結・吸収）。太字は新しい攻撃の解放。データは `tree-fort-data.js`（ノードを足すだけで増やせる）。
- 戦闘: `tree-fort-battle.js`（描画なし）。敵は grunt / runner（3 波〜）/ tank（5 波〜）、波ごとに数と体力が増える。`simulate()` で画面なしにバランスを確認できる（目安: 初期 約 3 波、序盤 5〜6、中盤 10、全開放 18）。
- 保存: `Store.load/save`（`core/storage.js`）。キー `tree-fort-save`（取得ノード・ポイント・ベスト波・スキン・演出）。
- **ショップ**: ポイントで「スキン」（ネオン=無料 / 虹 150 / モダン 200 / 和 250）と「演出」（標準=無料 / 幾何学 180 / 曼荼羅 280）を買える。行をタップするとその場でプレビュー（買うまで装備されない）。
  - スキン: 背景・色・光り方・ノード・敵・砦・弾・雷・爆発・粒（和は桜）・書体まで変わる（`tree-fort-skins.js`）。スキンの追加は SKINS に 1 つ足す。
  - 演出: 幾何学（入れ子の多角形・星型多角形・黄金角の螺旋・バラ曲線・正弦波の干渉）/ 曼荼羅（8〜12 方向の対称・万華鏡・スピログラフ）。スキンと独立に組み合わせられる（4×3 = 12 通り）。
- 描画は `tree-fort-view.js`（状態を持たない）、画面ロジックは `tree-fort.js`。戦闘の演出は `b.fx`（id つき）を拾って出す（粒・画面の揺れ・フラッシュ・効果音 = `Sound.noise` を追加）。
- 入力: `Input.released`（離した瞬間）を追加。押す・離すが同じフレームのクリックでも取りこぼさない。
- テスト: `works/collection/tests/tree-fort.test.mjs`（データ・戦闘・バランス）/ `tree-fort-ui.smoke.mjs`（12 通りの描画が例外なく動く）。

## ツリー砦の武器（12 種・Lv1〜5・組み合わせ効果）
- 武器: 爆弾 / 雷撃 / 回転刃 / 火炎放射 / 氷結弾 / 毒霧 / ミサイル / レーザー / 地雷 / 重力井戸 / 流星 / ドローン。それぞれ Lv1〜5（Lv3・Lv5 で動きが変わる）。データと動きは `tree-fort-weapons.js`（`WEAPONS` に足して `upd` に動きを書く）。
- 装備枠: 主砲（弾）は常に装備。武器は枠制（初期 3、ポイントで最大 6。4 枠目 120 P / 5 枠目 300 P / 6 枠目 600 P）。何を組み合わせるかを選ぶ遊び。
- 入手: ポイントで「武器庫」から解放・強化。ツリーの 爆弾砲・雷撃・回転刃 ノードは、それぞれ Lv1 を無料で解放する（戻すと、強化していない分は消える）。
- 状態異常: 燃焼・毒（継続ダメージ）/ 鈍足 / 凍結（凍結の直後は少し効きにくい）。戦闘本体は `tree-fort-battle.js`。
- 組み合わせ効果（11 通り、両方を装備すると発動）: 蒸気爆発（火+氷）/ 感電粉砕（氷+雷）/ 毒ガス引火（毒+火）/ 圧縮爆発（重力+爆弾）/ 毒の渦（重力+毒）/ 誘導地雷（地雷+重力）/ ドローン雷・氷・光（ドローン+雷/氷/レーザー）/ プリズム（レーザー+氷）/ 燃える大地（流星+火炎）。発動すると画面に名前が出て、専用の演出（スキン・演出パックに連動）が出る。
- 戦闘画面: 上のバーの下に、波の進み具合の帯と「あと N 体」（出現待ちを含む）。波の合間は「次の波まで N 秒」。
- 画面: 武器庫（武器の一覧・強化・装備・枠の購入 / 組み合わせ一覧、発動中は光る）。描画は `tree-fort-wview.js`。
- 保存: `weapons`（id → Lv）/ `loadout`（装備中の id）/ `slots`。古い保存データは、解放済みの武器を自動で装備して引き継ぐ。
- テスト: `tree-fort-weapons.test.mjs`（武器の整合・全武器が動く・状態異常・11 通りの発動・バランス）。バランスの目安（中盤の砦）: 武器なし 約 11 波 / 単体 Lv1 で +1〜2.5 / Lv5 で +3〜7 / 組み合わせると単体より遠くへ / 全ツリー + 6 枠 Lv5 で 約 33 波。

## かべレースの CPU
- `wall-race-cpu.js`: 評価 =（相手の最短手数 − 自分の最短手数）+ 0.4 ×（残り壁の差）。かんたん=最短経路中心＋ミス、ふつう=1 手先（ゆらぎあり）、つよい=2 手先読み。
- CPU 戦のベストは難易度別の「勝った回数」（`wall-race-<level>`）。

## 共通基盤
- シェル（`src/main.js`）がメニュー・開始待ち・ゲームオーバー・ハイスコアを担当。
- ゲームは `create(env)` で `{ reset, update, draw, score }` を返すだけ。
- ハイスコアは localStorage（使えない環境ではメモリのみ）。

## 公開
- GitHub Pages で公開する方針（確定）。ホーム画面追加用に `manifest.webmanifest` とアイコン（`works/collection/make_icons.py` で生成）を用意済み。
- 公開前に、名称・素材がオリジナルであることを確認する。公開（リポジトリ作成・push）は実施前に再確認する。

## ツリー砦のローグライト化（実装済み）
- ステージ 10（各 10 Wave + ボス）・エンドレス（ステージ 3 クリアで解放）・毎日のチャレンジ。難度は `GSTEP`(3.1) で上がる。
- 戦闘中は経験値でレベルアップ → 3 択（武器・能力）。リロールあり。武器・組み合わせ・遺物は「拾うまで ？？？」で、図鑑に記録（素材のヒント付き）。
- 遺物 16 種（精鋭の宝箱から）、契約 5 種（Wave 3・6 の途中）、オーバードライブ（ゲージ満タンで 8 秒強化）、★3 段階、実績 12、コンボ。
- ステージ修飾（swift/horde/fog/plated/rush/regen/haunt/wealthy）。倍速 ×1/×2/×3。
- 保存は v2。v1 の武器購入は初回読込時に一度だけ返金して移行。
- バランス目安（bot 8 回）: ステージ 1〜3 ほぼクリア、4〜7 は半々、9〜10 は 5〜6/8。遺物は 1 回 2〜8 個程度。

## ポータル（最初の画面）の 3 世界
- 世界（タブ）: ケータイゲーム集（8bit・緑の LCD）／対戦・ボード（やわらかい夜色）／パズル＆戦略（ネオン）。ゲームは registry の `world` で振り分ける。`genre` は将来の絞り込み用（1 世界が 10 本を超えたらチップを足す）。
- ツリー砦は「ルーンタワー」に改名（id は `tree-fort` のまま。保存データは引き継がれる）。
- 一覧はドラッグでスクロール。ゲームは指を離したときに選ばれ、約 6px 動いたらスクロール扱い。
- 画面の配色・角の丸み・光・書体・背景の動きは、タブ切替で約 0.6 秒かけて補間。BGM は曲（譜面）が 1 つで、世界ごとに音色（`core/music.js` の TIMBRE）だけが違い、切替時に音量をクロスフェードする。音は最初のタップまで鳴らせない（ブラウザの仕様）。♪ ON/OFF は保存。
- 音色は世界ごとに別の曲にもできる（譜面を `MELODY` から世界別にする）。
