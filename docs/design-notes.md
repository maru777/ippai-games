# 設計メモ

## 方針（確定）
- Web（HTML5 Canvas）、素の JS、依存なし。スマホのタッチ優先、PC はキーボード対応。
- 論理解像度 240×320。4 色パレットのドット風。
- 年代は 2000 年代半ば（i アプリ・Flash 全盛期）基準。

## ループパズル（予備に移動）
- 名称はニコリの商標を避け「ループパズル」。ルールのみ採用。
- 問題は事前生成の固定問題（5×5 を 30 問程度）。生成スクリプトで解の一意性を検証して `data/` に置く。

## 補足
- 入力は `Input.pointers` でマルチタッチに対応（マリさんの冒険の左右＋ジャンプ同時押し用）。
- マリさんの冒険のステージは `STAGES`（ビルダー関数）で定義。ゲームを足す場合も同様にデータで増やせる。
- マリさんの冒険の名称・キャラ・素材はオリジナル（任天堂作品の素材は不使用）。

## オンライン対戦（かべレース）
- 中継は Cloudflare Workers + Durable Objects の汎用中継（`works/online/server/`）。ルームコードは 4 桁の数字、接続元 Origin を制限。
- 判定は各ブラウザが同じルール（`wall-race-rules.js`）で行い、手だけを送り合う。接続先は `src/core/config.js` の `RELAY_URL`（または URL の `?relay=`）。
- 4 桁は推測されやすい（約 1 万通り）。無料枠の消費対策は Origin 制限に依存する。

## かべレースの先手・後手とチャット
- 先手・後手はランダム（CPU 戦は開始時、オンラインは部屋を作った側が抽選して `start` で通知）。
- チャットはオンライン対戦のみ。定型スタンプ（絵文字 8 種。番号で送信）と自由入力（30 文字まで）。送信は 1 秒に 1 回まで、自由入力は相手側で「文字:非表示」にできる。サーバーは中身を解釈しない（再デプロイ不要）。
- 画面上部にログ（3 行・上下ドラッグかホイールでスクロール、約 50 件保持）と、直近のスタンプ枠（3 秒）を置き、盤面には重ねない（盤面の上端は y=62）。
- 自由入力は HTML の `input` を画面下に重ねる。`core/input.js` は `input` 要素への打鍵をゲーム操作として扱わない。

## かべレースの CPU
- `wall-race-cpu.js`: 評価 =（相手の最短手数 − 自分の最短手数）+ 0.4 ×（残り壁の差）。かんたん=最短経路中心＋ミス、ふつう=1 手先（ゆらぎあり）、つよい=2 手先読み。
- CPU 戦のベストは難易度別の「勝った回数」（`wall-race-<level>`）。

## 共通基盤
- シェル（`src/main.js`）がメニュー・開始待ち・ゲームオーバー・ハイスコアを担当。
- ゲームは `create(env)` で `{ reset, update, draw, score }` を返すだけ。
- ハイスコアは localStorage（使えない環境ではメモリのみ）。

## 公開
- GitHub Pages で公開する方針（確定）。ホーム画面追加用に `manifest.webmanifest` とアイコン（`works/collection/make_icons.py` で生成）を用意済み。
- 公開前に、名称・素材がオリジナルであることを確認する。公開（リポジトリ作成・push）は実施前に再確認する。
